REQ-BRW-003: SpiderMonkey JSContext 融合

servo 拥有全局唯一 JSEngine，每个 ScriptThread 持有自己的线程局部 JSContext（servo script_runtime.rs 的 RustRuntime::get() 是 thread-local slot）。Bao 的 Node.js/Bun host functions 注册到各 ScriptThread 的 JSContext 中。选择 SpiderMonkey 的目的就是与 servo 共享同一引擎（JSEngine），实现真正融合。

架构原则

Bao 是统一库，servo 和 Node.js API 始终共存。全局唯一 JSEngine；每个 servo ScriptThread 在自己的 OS 线程持有线程局部 JSContext（SM 标准多线程模型：1 JSEngine + N per-thread JSContext，servo script_thread.rs 每页一线程 spawn）。Bao 的 host functions（console/require/fs/path/crypto/http 等）注册为各 ScriptThread JSContext 的全局对象。同一 JSContext 内同时存在 Web API 和 Node.js API，无任何转换层。

验收标准

  • C1: 全局唯一 JSEngine，每个 servo ScriptThread 持有线程局部 JSContext（servo script_runtime.rs RustRuntime::get thread-local slot；bao 不创建独立 JSEngine）。【BCE-20260621-001 修正：原「整个 Bao 仅一个 JSContext」与 servo 上游现实冲突，已废止】
  • C2: 所有 JS 求值经 servo::register_script_thread_callback 投递到 ScriptThread 单一消费者串行执行；主线程通过 drain_callbacks 轮询取回 Arc OnceLock EvaluateResult（满足 SM 单线程约束）
  • C3: Bun/Node host functions（console/require/fs/path/crypto/http）必须在 ScriptThread 初始化期注册，禁止在其他 OS 线程注册
  • C4: 主线程（含 PagePool/CDP 路由/CLI）禁止直接调用 SM API（*mut JSContext / *mut JSObject / JS::* 函数），跨线程 JS 操作必须封成 ConcurrentTask 投递回 ScriptThread
  • C5: Node Realm 与 Page Realm 物理隔离 — evaluate_js_web 在 Page Realm(Window) 执行只有 Web API，Compartment 隔离保证 Page Realm 无法发现 Node Realm 的任何对象
  • C6: evaluate_js 可信脚本通过 EnterRealm(Node) 切换到 Node Realm 执行，拥有 Node.js + DOM 全权限
  • C7: Node Realm global 上注册 console/require/fs/path/crypto/http 等 Node.js API
  • C8: GC 由 servo spin_event_loop() 统一管理，两个 Realm 共享同一 GC
  • C9: 无 JSEngine 重复初始化，Node Realm 通过 JS_NewGlobalObject 在 servo JSContext 上创建
  • C10: 禁止跨线程传递 JSObject 裸指针 — JSObject 归属于创建它的线程的 JSContext，跨线程访问违反 SM 线程/context 所有权，会破坏 activation 栈导致 SIGSEGV。bao 层不得在跨线程结构（DashMap/Mutex/全局 static）中持有 JSObject 裸指针，跨线程只传 PageId/句柄/序列化数据（BCE-20260621-001，根治 PagePool 混沌 SIGSEGV）
  • C11: bao 初始化 servo 时必须设 opts.disable_script_debugger = true — 跳过 servo ScriptThread 的 fire_add_debuggee（bao 用自己的 bao_cdp，不需 servo devtools），避免 Realm::setIsDebuggee → BaselineInterpreter::toggleDebuggerInstrumentation → 后续 OSR initForOsr 解引用 NULL activation 链导致 SIGSEGV。该约束由 servo 上游 patch（opts.rs 新增 disable_script_debugger 字段 + script_thread.rs 守卫）+ mozjs 上游 patch（BaselineFrame.cpp initForOsr 加 activation 链 NULL 守卫）共同根治。2026-06-21 用户书面授权破例 patch servo/mozjs 上游，仅限 BCE-20260621-002（详见 src/BUG-KNOWLEDGE.md）

NFR-MEMSAF-001: SpiderMonkey JSContext 单线程串行化(全项目级内存安全不变式)

SpiderMonkey JSContext(*mut JSContext)及所有派生 GC 对象(*mut JSObject / JS::Value / JS::Handle)具有 OS 线程亲和性:仅可在 servo ScriptThread 单一消费者线程上调用 SM API。本 NFR 把 BCE-007(INV-5 仅覆盖 fetch_async 跨线程场景)泛化为全项目级不变式,约束所有跨线程接触 SM 指针的路径。

  • INV-MEMSAF-1: 禁止任何 OS 线程(除 servo ScriptThread)直接调用 SM API(*mut JSContext / *mut JSObject / JS::Handle / JS::* 函数)
  • INV-MEMSAF-2: 所有 JS 求值经 servo::register_script_thread_callback 投递到 ScriptThread 单一消费者串行执行,主线程通过 drain_callbacks 轮询 Arc OnceLock EvaluateResult 取回(零跨线程 SM 指针)

NFR-THREAD-SAFETY: 禁止跨线程 JSObject 裸指针 (BCE-20260621-001 根治不变式)

JSObject(*mut JSObject)归属于创建它的 servo ScriptThread 的线程局部 JSContext。servo 上游 (components/script/script_thread.rs:527 thread::Builder spawn "Script#{id}")每个 pipeline spawn 独立 OS 线程,持有线程局部 JSContext(script_runtime.rs:740 RustRuntime::get() thread-local slot; SAFETY: "only one JSContext can exist on the thread")。全局 1 JSEngine + N 个线程局部 JSContext = SM 标准多线程模型。跨 OS 线程持有/解引用另一 ScriptThread 创建的 *mut JSObject 会破坏 SM activation 栈导致 SIGSEGV(BaselineFrame::initForOsr interpActivation != Interpreter)。

根因(BCE-20260621-001): 原 NODE_REALMS / PAGE_GLOBALS(DashMap<usize,usize>) 与 LAST_PAGE_GLOBAL(AtomicUsize)三个进程级 static 存的是 *mut JSObject 裸指针。evaluate_js_via_node_realm / inject_node_apis_with_stealth 跨线程取出另一 ScriptThread 的 JSObject 裸指针 + AutoRealm → activation 栈破坏 → PagePool 混沌测试 SIGSEGV。

根治: 所有跨线程存储改用 WebViewId(Copy+Hash+Eq,stable across navigation) 作为 key,值仍存 *mut JSObject 但仅在 owning ScriptThread 的 callback 内解引用;LAST_PAGE_GLOBAL 进程级 AtomicUsize 消除(改 per-WebViewId OnceLock / 直接参数传递);lazy_dom_getter 改 thread_local! PER_THREAD_PAGE_GLOBAL(ScriptThread-local,无跨线程访问)。

不变式(INV)

  • INV-TS-1: 禁止在进程级 static(DashMap/Mutex/AtomicUsize/AtomicPtr 等)中存 *mut JSObject 裸指针作为跨线程共享。bao 层跨线程结构只能存 WebViewId/PageId/句柄/序列化数据(Send+Sync 类型)
  • INV-TS-2: *mut JSObject 裸指针仅在创建它的 ScriptThread callback 内可见;主线程读到的裸指针必须仅作为不透明 address 传给下一个同 WebViewId 的 callback(servo 路由保证同线程),不得在主线程直接调用 SM API
