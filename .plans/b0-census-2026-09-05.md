## 3. Ranking + top-3 transposition slice candidates

Rank order applied: `correctness/lifecycle > resource ownership > host-process safety > simplification > performance`.

### Candidate 1 — Kill env mutation in `BaoRuntime::new()` (UNBLOCKED)
- Object: `src/bao_runtime/src/runtime.rs:43-55` (`init_env_aliases` → `std::env::set_var`).
- Label: RUNTIME-LOCALIZE.
- Why highest: rank-1 correctness/lifecycle — a library constructor irreversibly mutates host process global state; `set_var` is UB-adjacent in multithreaded hosts (glibc getenv/setenv race); a second runtime silently inherits/fights the first runtime's alias writes; breaks clean Drop/redo semantics and test isolation. Hottest library entry point (`bao::BaoRuntime::new`).
- Unblocked: pure bao-layer change — snapshot `BAO_*` into runtime-owned config and consume at env read points (resolver/env helpers), preserving observable alias behavior. No upstream dependency, no product semantics change. Tests straightforward (env unchanged after new+drop; aliases still honored).

### Candidate 2 — Per-runtime H2 stealth fingerprint (UNBLOCKED)
- Object: `src/bao_stealth/src/http2.rs:186` (`GLOBAL_HTTP2_FINGERPRINT`).
- Label: RUNTIME-LOCALIZE.
- Why: correctness in the stealth product domain (REQ-STL) — two runtimes with different profiles cross-contaminate the single H2 fingerprint while TLS/JS fingerprints are per-realm → detectable TLS-vs-H2 inconsistency, a product correctness defect under multi-runtime embedding.
- Unblocked: bao-layer; the per-realm keying pattern already exists (`src/bao_stealth/src/engine_props.rs:333` `REALM_PROFILES: DashMap<usize, Arc<RealmProfile>>`).

### Candidate 3 — Detached-thread lifecycle ownership on runtime drop (UNBLOCKED, largest)
- Object: row 43 cluster — start with `src/bao_browser/src/lib.rs:574` CDP server thread (stop-signal + join via the existing `BaoRuntime::drop`/`close_all` path), then WS-connect slot, then per-op fs/crypto/build completion threads.
- Label: TASK-TRANSPOSE.
- Why: rank-1 correctness/lifecycle — threads outlive `BaoRuntime::drop` and may touch channels/slots/mini-loops after teardown; resource ownership — thread leaks per runtime cycle. Mechanism is already thread-based; the remaining work is ownership (cancel → drain → join), exactly plan §2's "process lifecycle → explicit start/cancel/drain/join/drop".
- Unblocked (engineering-internal); slice further if needed (CDP server thread first as the bounded v1).

### Blocked (documented, not top-3)
- Row 17 servo per-runtime Opts — blocked on servo upstream process-global `OnceLock<Opts>` (needs servo-side window; already mitigated for collision).
- Row 19 `NODE_REALM_BY_WEBVIEW`/`PAGE_GLOBAL_BY_WEBVIEW` multi-instance keying — blocked on #23 SM Realm topology scoping decision.
- Row 21 console timers/counter scoping — blocked on product-semantics ruling (Node console is process-global; multi-runtime meaning is a user adjudication).

1. Implement Candidate 1 (env alias localization) — bounded, rank-1, unblocked.
2. Implement Candidate 2 (per-runtime H2 fingerprint) — bounded stealth-correctness fix.
3. Implement Candidate 3 v1 (CDP server thread stop+join on drop) — lifecycle ownership.
4. Fold the remaining weak RUNTIME-LOCALIZE rows (22/23/24/25/27/28/29/30) into B1 runtime/thread-ownership work; revisit blocked rows 17/19/21 when their blockers resolve.
