06-ACCEPTANCE — 业务验收/PRD-NFR/PRD-SLA

PRD-REQ-UNIFIED-RUNTIME 单一运行时全能力始终在线

安装一个 bao 即得到完整能力面:JS 脚本执行、无头浏览器、Node.js/Bun 生态 API、反指纹防护同时在线,无模式切换、无需另装 Node.js 或 Chrome。浏览器能力不是可选插件,统一运行时是产品形态本身。(SPEC 映射:REQ-ENG-001、REQ-ENG-003、REQ-ENG-004、REQ-BRW-003)

用户故事: PRD-USERSTORY-LIBAUTHOR
业务场景: PRD-SCENARIO-RUN-TS-SCRIPT
同一脚本内 require('node:fs') 与 document.querySelector 共存可用
不存在「启用浏览器」开关:浏览器能力默认在线
无需安装 Node.js 或 Chrome 即可跑脚本与渲染页面

PRD-REQ-SCRIPT-RUN 直接运行 JS/TS 脚本,TS 免预编译

开发者用 bao run 直接执行 .js 与 .ts 文件,TypeScript 免预编译免配置;ESM 模块与 node_modules 第三方依赖解析开箱正常;出错时报出带 stack trace 的异常而非静默退出。(SPEC 映射:REQ-CLI-001、REQ-ENG-001、REQ-ENG-005)

用户故事: PRD-USERSTORY-WEBDEV
业务场景: PRD-SCENARIO-RUN-TS-SCRIPT
bao run index.ts 直接出运行结果,无预编译步骤
ESM import 与 node_modules 依赖解析正常
脚本异常带 stack trace 输出

PRD-REQ-TOOLCHAIN 一条命令的开发工具链(test/build/install)

开发者用 bao 完成日常开发循环:bao test 跑测试、bao build 打包产物、bao install 装依赖,各一条命令,不依赖外部 Node 工具链。本条 draft 起步:验收以三条工具链命令可用性为要点,SPEC 侧补强 REQ 缺口已登记(待后续波)。(SPEC 映射:REQ-CLI-001)

用户故事: PRD-USERSTORY-WEBDEV
业务场景: PRD-SCENARIO-JEST-TEST, PRD-SCENARIO-BUILD-FRONTEND, PRD-SCENARIO-INSTALL-DEPS
bao test 以 Jest 兼容风格运行测试并输出结果
bao build 产物可直接运行
bao install 完成依赖安装

PRD-REQ-BUN-COMPAT Bun 生态兼容:现有 Bun 程序原样运行

为 Bun 编写的服务端代码迁移到 bao 不需要改源文件:Bun.serve 起 HTTP 服务、Bun.file 读文件、fetch 取远端、Bun.write 写盘、Bun.$ 管道 Shell、listen/connect/udpSocket 网络原语全部可用;全局命名空间 Bao.* 是 Bun.* 的别名且指向同一对象;fetch 等异步 IO 不阻塞脚本主线程。(SPEC 映射:REQ-ENG-006、REQ-ENG-010、REQ-BAO-API-017、REQ-BAO-API-018)

用户故事: PRD-USERSTORY-WEBDEV, PRD-USERSTORY-FULLSTACK
业务场景: PRD-SCENARIO-HTTP-SERVER
serve/file/fetch/write、Bun.$、listen/connect/udpSocket 可用
Bao.* 与 Bun.* 是同一对象(Bao.* === Bun.*)
fetch 发起后脚本继续执行,不阻塞

PRD-REQ-NODE-COMPAT Node.js 生态兼容:常用 Node 脚本直接运行

依赖 Node.js 标准库与惯例的既有工程在 bao 上直接跑:node:fs、node:path、node:http、node:crypto、node:tls 内建模块行为对齐,Buffer 与 process 全局按 Node 语义工作,CommonJS require 与 ESM import 双模块形态都能加载真实第三方包。(SPEC 映射:REQ-ENG-007)

用户故事: PRD-USERSTORY-WEBDEV
业务场景: PRD-SCENARIO-RUN-TS-SCRIPT
node:fs/path/http/crypto/tls 内建模块可用
Buffer 与 process 全局按 Node 语义工作
require 与 ESM import 均可加载第三方包

PRD-REQ-BUILTIN-DATA 内置数据与系统能力(sqlite/ffi/vm)

数据与系统能力开箱即用,不需要原生编译或额外安装:bun:sqlite 嵌入式数据库直接建表读写;bun:ffi 直接调 C 共享库函数;node:vm 沙箱可注入全局对象且与宿主全局隔离。(SPEC 映射:REQ-ENG-008、REQ-ENG-009、REQ-ENG-011)

HTML/CSS 页面在无窗口环境下渲染成图片:Flexbox、Grid、文字排版正确呈现,输出 PNG/JPEG/WebP 格式截图;不依赖窗口系统,服务器与容器内可用。(SPEC 映射:REQ-BRW-001、REQ-BRW-002)

用户故事: PRD-USERSTORY-FULLSTACK, PRD-USERSTORY-SCRAPER, PRD-USERSTORY-QA

无窗口系统环境(服务器/容器)可用

PRD-REQ-MULTIPAGE 多页面并行管理,长爬不污染

一个运行时同时打开多个相互隔离的页面做长爬任务,上下文互不污染:页面可创建、切换、关闭;页面之间 JS 状态隔离;空闲页面可自动回收,回收阈值参数留 SPEC 定义。(SPEC 映射:REQ-LIB-001、REQ-LIB-002)

用户故事: PRD-USERSTORY-SCRAPER, PRD-USERSTORY-LIBAUTHOR
业务场景: PRD-SCENARIO-MULTIPAGE-CRAWL
页面可创建、切换、关闭
页面间 JS 状态相互隔离
空闲页面自动回收(idle_ttl/max_total 参数留 SPEC)

PRD-REQ-PAGE-SCRIPT 页面脚本双环境:Web API 沙箱与可信全权限

页面脚本双环境:普通页面里执行的 JS 只能看到 Web API(安全),物理拿不到 Node 能力;可信脚本则同时拥有 Node API 与 DOM 全权限(强大)。两档环境由页面/脚本来源显式区分。(SPEC 映射:REQ-BRW-003)

业务场景: PRD-SCENARIO-UNTRUSTED-SCRIPT-SANDBOX, PRD-SCENARIO-TRUSTED-SCRIPT-FULL-POWER
普通页面 JS 物理拿不到 Node API
可信脚本同时可用 Node API 与 DOM
环境档位由来源显式区分,非运行时探测

PRD-REQ-WEB-WORKER 浏览器 Web Worker 并行

页面内可用标准 Worker 并行执行任务,按 Worker 类型分层承诺:DedicatedWorker 与 SharedWorker 为承诺能力;ServiceWorker 仅承诺注册与生命周期管理,fetch 拦截显式排除于 PRD 验收(裁定记录 DEC-WK-008,blocked-on-human-decision)。通信与生命周期:postMessage 通信、terminate 终止、结构化克隆传值符合 Web 惯例;worker 内的反指纹呈现与主线程一致;反复创建销毁不崩溃不泄漏。(SPEC 映射:REQ-BRW-004、REQ-BRW-4 worker 家族)

业务场景: PRD-SCENARIO-WORKER-FINGERPRINT-CONSISTENCY
DedicatedWorker:new Worker() 可用,postMessage/terminate/结构化克隆符合标准
SharedWorker:构造函数存在且可创建共享 Worker(承诺能力)
ServiceWorker:仅验收注册与生命周期;fetch 拦截显式排除于 PRD 验收(DEC-WK-008)
worker 内指纹与主线程一致
反复创建销毁不崩溃

用户故事: PRD-USERSTORY-SCRAPER, PRD-USERSTORY-SECURITY

PRD-NFR-LEGAL-BRAND 法律合规与品牌边界

目标: MPL-2.0(SpiderMonkey/servo)与 MIT(Bun crates)双许可证合规分发;分发物保留 Bun 上游版权与许可声明;不以 Bun 商标命名或推广产品,不暗示 Bun 官方 endorse Bao。

理由: Bao 大量复用 Bun crates(MIT)与 SpiderMonkey/servo(MPL-2.0)代码,许可合规与品牌边界是产品对外发布(含 crates.io 已发布的 170 个库)的法律前提;违反商标或许可义务将直接阻断分发。分层边界:性能/容量/安全等工程内部 NFR 不入 PRD,归宿 SPEC(现有 9 条 SPEC NFR 承接),本条是唯一产品侧 NFR。
